# ConditionLoggingSystem

Multi-device telemetry collection system for Raspberry Pi  
**Flask版（2026-07時点）**

## 1. システム概要

本システムは、設置環境の気象情報および駆動端末のハードウェア状態を包括的に記録・集約する「コンディションロギングシステム」です。

**2-Tier 分散アーキテクチャ**を採用し、  
- **子機（Tier 1）**: Raspberry Pi Zero 2 W（省電力計測端末）  
- **親機（Tier 2）**: Raspberry Pi 4B（常駐集約サーバー）  

に役割を完全分離しています。

従来の課題であった「エッジ端末のサイレント・デス（ハングアップ）」を、HTTP POST + ローカルSQLite退避 + 親機Flask受信の構成で根本解決しています。

## 2. 全体構成図

```
【子機：Zero 2 W】（15分ごと）
    │
    ▼
[BME280 センサー] → 温度・湿度・気圧を測定
    │
    ├─ 通信成功時 → SDカード書き込みなしで即時送信
    │
    └─ 通信失敗時 → ローカルSQLite3 (retry_queue.db) に退避
            │
            ▼ (Wi-Fi復旧後)
    HTTP POST (Flask API) ───(おうちWi-Fi)───► 【親機：Raspberry Pi 4B】
                (X-API-Key 付き)

──────────────────────────────────────────────────────────────

【親機：Raspberry Pi 4B】（常駐サーバー）

    【Flask レシーバー】（ポート: 8000 で待機）
        │
        ├─ ① APIキー認証
        ├─ ② シンプルデータチェック
        └─ ③ SQLite3 に保存（WALモード + busy_timeout + リトライ）
                │
                ▼
    [condition_logging.db] （保存先: /home/hideo_81_g/condition_logging/）
        ├── zero2w_logs テーブル （Zero 2 Wデータ）
        └── rpi4b_logs テーブル   （4B自身の測定データ）

    ▲
    │ (15分ごと)
[4B測定スクリプト] ──直接DB書き込み──► rpi4b_logs
    （AHT25：温度・湿度）

    │ (定期)
    └─ rclone → Googleドライブへバックアップ
```

## 3. 収集するテレメトリデータ

### 環境テレメトリ（現在実装対象）
| 端末 | センサー | 測定項目 |
|------|----------|----------|
| Zero 2 W | BME280 | 温度・湿度・気圧 |
| Raspberry Pi 4B | AHT25 | 温度・湿度 |

### システムテレメトリ（次ステップ）
- バッテリー残量（PiSugar）
- Wi-Fi電波強度（RSSI）
- その他デバイス固有メトリクス

※ まずは Zero 2 W ↔ 4B ↔ Google Drive の3点連携を優先し、システムメトリクスは後続で実装する。

## 4. 主要コンポーネント

| コンポーネント       | 場所      | 役割                         | 使用技術              |
|----------------------|-----------|------------------------------|-----------------------|
| センサー読み取り     | Zero 2 W  | BME280からデータ取得         | smbus2                |
| ローカル退避         | Zero 2 W  | 通信失敗時の安全保管         | SQLite3 (WAL)         |
| 送信クライアント     | Zero 2 W  | 4Bへデータ送信               | requests / urllib     |
| レシーバー           | 4B        | データ受信窓口               | Flask                 |
| データベース         | 4B        | 全データ一元集約             | SQLite3 (WALモード)   |
| 4B自身の測定         | 4B        | AHT25測定 → 直接DB書き込み   | smbus2 + sqlite3      |
| クラウドバックアップ | 4B        | Googleドライブ同期           | rclone                |

## 5. 設計上のポイント

- **センサー構成**: Zero 2 W = BME280 / 4B = AHT25
- **SDカード保護**: Zero 2 Wは「成功時は書き込みゼロ」、失敗時のみローカルSQLiteへ退避
- **4B自炊データ**: HTTPを通さず直接DB書き込み（効率重視）
- **DB書き込み安全性**: WALモード + busy_timeout + 簡易リトライを両書き込み経路に適用（同時書き込み対策）
- **タイミング**: Zero 2 W と 4B は独立タイマー（同期なし）。早い・遅い・ほぼ同時の各ケースを考慮
- **将来拡張**: `device_id` で区別しているため、子機の追加が容易
- **認証**: X-API-Key による簡易認証（同一LAN内運用前提）
- **耐障害性**: 通信断時もデータを失わないローカルキュー
